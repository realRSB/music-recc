# 2026-08-08

## decisions

- Set the working product name to Inner Horizons.
- Defined the product as a Spotify-powered discovery app that analyzes a user's playlist or song choices and recommends same-vibe new artists and songs.
- Chose a quick recommendation-maker flow over a long quiz.
- Decided recommendations should be individual songs assembled into a playlist, with short explanations for why each track fits.
- Decided Spotify login is required for account-specific actions like reading private playlists and saving generated playlists, but lightweight song or public-playlist discovery should not require user login when possible.
- Noted that new Spotify Web API use cases should not depend on deprecated recommendation, audio-features, audio-analysis, or related-artists endpoints.
- Chose a metadata and search based MVP recommendation strategy so development can proceed without restricted Spotify endpoints.
- Added repo workflow rules to `docs.md` for other agents.
- Chose a lightweight React and Vite app foundation for the first MVP UI.
- Decided to add a browser smoke test so the first UI can be verified beyond the production build.
- Corrected the MVP direction to use a real Express backend for Spotify OAuth, playlist/song analysis, recommendation generation, and save-to-playlist actions instead of static sample recommendations.
- Decided the frontend should be split into app, API client, components, and styles so future agents can work without editing one giant file.
- Added logged-in playlist loading through Spotify's current-user playlists endpoint so users can select one of their own playlists as the recommendation source.
- Removed mood from the recommendation flow so the app now uses playlist/song source plus the three discovery distances: same vibe, slightly new, and deep cut.
- Retuned recommendations around source artists, source track names, inferred/Spotify genre lanes, novelty, and popularity fit instead of mood terms.
- Kept `SESSION_SECRET` required in production, but allowed local development to use an ephemeral session secret so missing env setup does not block testing Spotify login.
